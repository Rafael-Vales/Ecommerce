## Hallazgos

### Bloqueantes
1. No se pudo completar pago real hasta `PAID` en esta corrida.
   - Razones:
   - entorno CLI sin interaccion de navegador para completar checkout MP
   - `cloudflared` no instalado para exponer localhost por HTTPS

### Importantes
1. Si el webhook recibe `paymentReference` inexistente en MP, el endpoint hoy devuelve `500`.
   - Aunque persiste `PaymentEvent`, queda `processedAt = null` y el evento no se marca como procesado.
   - Esto impacta robustez operativa ante payloads validos pero con `data.id` no resoluble.

2. En `.env` local actual, `MERCADOPAGO_WEBHOOK_SECRET` y `PAYMENTS_RECONCILE_SECRET` estaban vacias.
   - En esas condiciones, webhook/reconcile siempre retornan `401`.
   - Para esta revision se uso override runtime temporal (sin modificar archivos) para poder validar.

### Mejoras recomendadas
1. En `processPaymentWebhook`, transformar error de fetch provider no encontrado en camino controlado (`ignored`) en vez de `500`.
2. Marcar `PaymentEvent.processedAt` tambien en casos de error recuperable para evitar eventos colgados.
3. Agregar runbook operativo para tunnel HTTPS local + credenciales sandbox MP.

## Estado final de la review
- Parcialmente aprobada para capa de checkout/idempotencia/reconciliacion/dedupe.

## Reproduccion rapida
1. Levantar app:
   - `PAYMENTS_RECONCILE_SECRET=<secret> MERCADOPAGO_WEBHOOK_SECRET=<secret> npm run dev`
2. Ejecutar checkout API:
   - `POST /api/checkout`
3. Consultar orden:
   - `GET /api/checkout/orders/:id?tenantSlug=rafa-petshop`
4. Reconciliar:
   - `POST /api/payments/reconcile` con header `x-reconcile-secret`
